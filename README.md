# أمل الطفولة — إدارة الجمعية

موقع عربي من اليمين إلى اليسار لإدارة مالية الجمعية والمنتسبين والمستفيدين والمساعدات والتقارير، بتصميم مستوحى من شعار أمل الطفولة.

## الوظائف
- إضافة وتعديل وحذف السجلات وأرقام تعريفية تلقائية، بما فيها ملفات العمال.
- بطاقات العمال والمستفيدين مع بياناتهم وأرقامهم، فرديًا أو دفعة واحدة حسب نتائج البحث.
- صورة شخصية قابلة للإضافة والتغيير والإزالة، وشعار الجمعية على كل بطاقة. تُحفظ نسخة JPEG مصغرة مع ملف الشخص.
- رمز QR قابل للمسح على كل بطاقة، يحمل رقمها فقط بصيغة `EMEL6VOLE:BEN-000002` أو `EMEL6VOLE:WRK-000001`. لا يحتوي على تفاصيل المستفيد ولا يفتح رابطًا عامًا.
- توليد QR محليًا باستخدام مكتبة Nayuki تحت ترخيص MIT؛ لا تُرسل بيانات الأشخاص إلى خدمة QR خارجية.
- تقارير PDF لكل قسم وملف وبطاقات؛ تفتح نافذة الطباعة، ثم اختر «حفظ بصيغة PDF». بطاقات المستفيدين تشمل بيانات الأسرة والتصنيفات وسجل المساعدات.
- تصنيف المستفيد ضمن أكثر من فئة هشاشة.
- سجل مساعدات مرتبط بملف المستفيد. المساعدات النقدية تحتسب ضمن المصروفات تلقائيًا.
- تقارير شهرية وسنوية وتصدير CSV وطباعة إلى PDF.
- قاعدة بيانات SQLite للتشغيل المحلي، وواجهة متوافقة مع D1 للاستضافة.
- سجل تدقيق لتعديلات البيانات.

## الحالة الحالية
الواجهة جاهزة واختبارات واجهة البيانات ناجحة. لم يُنشر الموقع بعد. إنشاء ترحيلات قاعدة البيانات وتجهيز الاستضافة ما زالا مطلوبين. لا تستخدمه لبيانات حقيقية قبل تأمين الاستضافة والتحقق النهائي.

## التشغيل بعد تنزيل الأدوات
يتطلب Node.js 24 أو أحدث.
```sh
npm install
npm run db:generate
npm test
npm run dev
```
ثم افتح http://localhost:3000. البيانات المحلية في `data/emel.sqlite`، وهي غير مضمنة في المستودع.

## البناء
```sh
npm run build
```
ينتج Worker في `dist/server/index.js`. يحتاج نشره إلى ربط D1 باسم `DB` وتطبيق ترحيلات `drizzle/`. الوصول إلى لوحة الإدارة يجب أن يكون خاصًا؛ الكود يعتمد في الاستضافة على سياسة وصول المنصة. التشغيل المحلي مخصص للتطوير فقط.

## ملاحظات مالية
- لا تسجل المساعدة النقدية مرة أخرى كمصروف؛ تُحتسب من سجل المساعدات.
- حالة اشتراك المنتسب لا تنشئ مدخولًا تلقائيًا؛ سجل المبلغ المستلم في المداخيل.
- تغيير العملة يغير وحدة العرض فقط.

## الحالة الحالية على Vercel

الموقع الآن معاينة للواجهة فقط، تفتح مباشرة دون كلمة مرور. إعدادات النشر في `vercel.json`، والبناء ينتج وظيفة وتوجيهًا عبر `.vercel/output`. لا توجد متطلبات لمتغيرات `ADMIN_PASSWORD` أو `DATABASE_URL` في وضع المعاينة.

واجهات القراءة تعيد سجلات فارغة؛ عمليات الحفظ معطلة، ولا تتصل النسخة المنشورة بقواعد البيانات أو تعرض سجلات حقيقية. ملفات الخلفية السابقة محفوظة للتطوير، لكنها لا تُضمّن في وظيفة المعاينة. الربط القادم سيكون عبر Supabase مع إضافة الدخول وصلاحيات البيانات في تلك المرحلة. لا تعتمد هذه النسخة لتخزين بيانات فعلية.

## صفحة الزوار

الصفحة الرئيسية `/` وصفحة `/visitors` تعرضان تعريف الجمعية ومجالات الرعاية والتعليم والحماية وطرق المساهمة والأسئلة الشائعة، بتصميم عربي متجاوب مع شعار الجمعية. لوحة الإدارة محفوظة في `/dashboard`. لم تُضف أرقامًا أو بيانات تواصل غير مؤكدة، ولا توجد خدمة دفع أو نموذج تواصل مربوط.

## ربط Supabase

أُضيف مشروع Supabase ومفتاحه العام في `supabase.config.json`، ويمكن استبدالهما بمتغيرَي `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` على Vercel. المفتاح العام ليس مفتاح إدارة ولا يُستخدم لتجاوز صلاحيات الصفوف.

- إعداد قاعدة البيانات: طبّق `db/supabase.sql` من SQL Editor أو الإضافة المربوطة. الملف ينشئ `emel_records` و`emel_audit` و`emel_memberships` مع RLS وتدقيق تلقائي للمساعدة والحذف. لا ينشئ حسابات ولا يمنح الزوار وصولًا.
- بعد إنشاء مستخدم Supabase Auth، أضف رقمه إلى `emel_memberships` بصلاحية `owner` أو `editor` أو `viewer`.
- الواجهة تفتح دون كلمة مرور كما هو مطلوب. قراءة السجلات الخاصة وحفظها يحتاجان جلسة Supabase لحساب مصرح له. التسجيل والدخول متاحان في صفحة `/account` برقم الهاتف وكلمة المرور.
- عند إضافة تدفق الدخول لاحقًا، مرّر جلسة Auth إلى `window.setSupabaseSession(session)`. رمز الوصول يُحفظ في ذاكرة الصفحة، وتتحقق واجهة البيانات منه عند Supabase ثم من عضوية الجمعية.
- زر «فحص الاتصال» في إعدادات المنظمة يتحقق من الوصول إلى REST API، ولا يثبت إنشاء الجداول أو صلاحيات المستخدم.

الجداول لم تُطبق والتحقق الحي لم يكتمل وقت تجهيز الربط. يحتاجان اتصال إدارة مشروع Supabase، ولا يكفي المفتاح العام لتنفيذهما.

## التسجيل بالهاتف وكلمة المرور

صفحة `/account` تضم تسجيل الدخول وإنشاء حساب برقم الهاتف الدولي وكلمة المرور، دون بريد إلكتروني. الحد الأدنى في نموذج إنشاء الحساب 6 أحرف، ويمكن أن يفرض Supabase سياسة أقوى.

يحوّل الخادم رقم الهاتف الموحّد إلى معرّف بريد داخلي ثابت (SHA-256) ويستخدم مزود Email، دون Twilio أو SMS. فعّل Email واترك Phone معطلاً، وعطّل Confirm email من Authentication → Sign In / Providers. لم يتغير هذا الإعداد تلقائيًا. الحسابات غير المؤكدة التي أُنشئت قبل تعطيله تحتاج تأكيدًا يدويًا من Users. لا يُثبت هذا الأسلوب ملكية رقم الهاتف، ولا يمنح التسجيل صلاحيات الجمعية تلقائيًا. البريد الداخلي لا يستقبل رسائل؛ استعادة كلمة المرور بالبريد غير متاحة، وتحتاج لاحقًا آلية مستقلة. حسابات مزود Phone القديمة لا تنتقل تلقائيًا إلى المعرّفات الجديدة.

تُحفظ جلسة Supabase في ملفات ارتباط HttpOnly وSecure مع تجديد رمز الوصول، ولا تعاد الرموز أو كلمة المرور إلى كود الواجهة أو سجل التطبيق. الحسابات الجديدة لا تُمنح صلاحيات تلقائيًا؛ تُضاف عضويتها في `emel_memberships` عبر الإدارة. صفحة الزوار ومعاينة لوحة التحكم تبقيان متاحتين دون حساب.

## ملف الانتساب الشخصي

صفحة `/profile` لحفظ معلومات المنتسب وصورته الاختيارية وعرض بطاقة ملف الانتساب وطباعتها. نفّذ `db/profiles.sql` مرة واحدة في Supabase SQL Editor. التخزين في جدول منفصل مع سياسات RLS تسمح لكل مستخدم بقراءة وتعديل ملفه فقط؛ لا تُخزن الصورة في بيانات JWT. الملف لا يمنح عضوية معتمدة أو صلاحية إدارة تلقائيًا ولا يضاف تلقائيًا إلى سجلات الإدارة. رمز QR يحمل UUID الملف فقط.

## ألوان الموقع ومساعد الجمعية

زر الألوان يقدم ثلاث لوحات ويحفظ الاختيار محليًا. مساعد الجمعية يجيب من دليل عام بالعربية والفرنسية. لتفعيل نموذج ذكاء اصطناعي فعلي، أضف `AI_GATEWAY_API_KEY` و`AI_GATEWAY_MODEL` إلى بيئة Production في Vercel، واختر معرّف نموذج موجود من قائمة AI Gateway الحية، ثم أعد النشر. المفتاح لا يُرسل للمتصفح. يستخدم الربط تلقائيًا `VERCEL_OIDC_TOKEN` في Vercel عند توفره ويختار نموذج Gemini Flash نصيًا من قائمة النماذج الحية دون معرّف ثابت. يمكن تجاوز النموذج باستخدام `AI_GATEWAY_MODEL`. دون مصادقة أو عند تعطل الخدمة تظهر إجابات الدليل بعنوان صريح؛ لا يُدّعى أنها توليد بالذكاء الاصطناعي. الأسئلة إلى 700 حرف والإجابة محدودة، وتحديد الطلبات المحلي احترازي لكل نسخة خادم وليس حدًا موزعًا عالميًا. المساعد لا يقرأ سجلات الجمعية الخاصة.

## فصل إدارة الجمعية عن الموقع العام

الموقع `/` والانتساب `/account` والملف `/profile` مستقلة عن `/admin`. دخول فريق الإدارة عبر `/admin/login` باسم مستخدم وكلمة مرور حساب Supabase المرتبط. لا توجد إمكانية إنشاء حساب إدارة من صفحة الدخول. يحدد `ADMIN_USERNAME` و`ADMIN_LOGIN_PHONE` الربط، أو القيم المقابلة في `admin.config.json`. تم تحديد اسم المستخدم وحساب الإدارة في admin.config.json. كلمة المرور الأولية محفوظة في متغير Vercel حساس `ADMIN_INITIAL_PASSWORD`؛ يمكن إنشاء حساب Supabase عند أول دخول صحيح، لكن منح دور owner يتطلب SQL من مالك المشروع ولا يمكن تنفيذه بالمفتاح العام. كلمات المرور لا تُحفظ في المستودع. يلزم حساب مصرح له في `emel_memberships` (owner/editor/viewer)؛ إنشاء حساب انتساب لا يمنح تلك الصلاحية. `/dashboard` يعيد التوجيه إلى `/admin`، والخادم يمنع تقديم HTML لوحة الإدارة لمن لا يملك الصلاحية.

## طلبات الانتساب

قسم «طلبات الانتساب» في لوحة الإدارة يظهر عند اختياره من القائمة فقط، ويعرض ملفات `/profile` مع أعداد الطلبات قيد المراجعة والمقبولة والمرفوضة، والبحث والتصفية وأزرار القبول والرفض. نفّذ `db/membership-requests.sql` مرة واحدة في Supabase SQL Editor بعد `db/supabase.sql` و`db/profiles.sql`. يضيف الملف حالة الطلب، ويسمح لفريق الإدارة بقراءة الطلبات، ويقصر القبول والرفض على owner وeditor عبر دالة `emel_review_profile`. لا يستطيع صاحب الطلب تغيير حالته، والقبول لا يمنح صلاحية لوحة الإدارة.
